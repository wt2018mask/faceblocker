# 2026-10-22 복구 및 보호 안정화

## 사용자 허용 후 실제 실행에서 추가로 확인한 사항

사용자가 60초 화면 테스트를 허용했다. 초기 패키지 앱은 시작/종료했으나 스크린샷 없는
Computer Use 입력은 `coordinate input geometry is unavailable`로 실패해 Start를 누르지 못했다.
화면 이미지를 외부로 보내지 않는 조건을 유지했다.

이후 `tools/LivePipelineProbe`로 생산 엔진 API를 직접 호출했다. 이 도구는 `--interactive`, 명시적
로컬 이미지 및 데이터 경로 없이는 창을 열지 않는다. 두 번의 8초 실제 캡처 구간, 40초 취소,
45초 자기 프로세스 종료 제한을 갖고 Escape/창 닫기/Ctrl+C 취소 처리가 있다.

첫 실행에서 캡처는 약 15 fps였고 실제 검출/트랙/오버레이 1개와 캡처 제외를 확인했지만,
검열되던 대상의 트랙이 남아 있는데 마스크가 0개가 되는 순간을 **FAIL로 재현**했다.
`CoverageGuard`를 추가해 이미 보호하던 트랙의 마스크 누락과 선택 영역의 낮은 신뢰도 후보를
전체 보호로 처리했다. 서로 다른 대상의 마스크로 다른 누락 대상을 대신 정당화하지 않는다.
선택 영역 후보가 검출되지 않는 완전한 false negative까지 해결한 것은 아니다.

중간 프로브에는 전 세션의 양성 여부를 다음 세션에 재사용한 assertion 오류가 있어 수정했다.
영역 수와 fail-closed 상태를 따로 읽던 통계도 불변 상태 한 개로 게시하도록 수정했다.
수정 후 headless 회귀는 **42/42 PASS**다. 실제 화면의 픽셀 정렬·키보드 비상키·모든 프레임의
무노출은 별도 검증 대상이다. `artifacts/live-pipeline-finalcheck.log`와 해당 데이터 루트의
`logs/app.log`에 숫자/상태만 남긴다. 화면 캡처나 영상은 저장하지 않는다.

보수적인 보호 정책 때문에 낮은 신뢰도 후보가 남거나 트랙이 소실 중이면 전체 화면이 더 오래
가려질 수 있다. 새 추론 시도만으로 해제하지 않는다. 기존 FailClosed 설정이 이 정책의 전체
화면 가림 여부를 제어한다. 사용자 Stop은 추론 결과와 별도로 창을 제거한다.

이 문서는 이번 세션에서 실행한 증거와 이전 에이전트의 기록을 구분한다.
실제 화면 오버레이의 깜박임이 완전히 해결되었다고 판정하지 않는다.

## 원치 않는 창과 터미널 현상

`artifacts/live-test/run-live.ps1`은 다음 동작을 했다.

- `viewer2.ps1`을 직접 실행해 테스트 이미지를 표시했다.
- 매 대기 루프에서 특정 제목의 터미널을 최소화했다.
- Guardian이 보호가 꺼진 것을 발견하면 다시 시작했다.
- 기존 VeilDesk 프로세스를 강제 종료했다.

실행 중이던 동일 스크립트 PID 18800을 CIM 명령줄로 확인한 뒤 그 프로세스만 종료했다.
Herdr/OpenCode 세션은 종료하거나 초기화하지 않았다. 관련 충돌 이벤트는 이번 조회에서 발견되지 않았다.
따라서 **터미널 최소화 경로는 확인**, **Herdr 자체 충돌 원인은 미확정**이다.

이전 viewer.ps1의 현재 원본에는 이미 실제 WPF Image를 `$picture`에 생성하는 코드가 있었다.
사용자가 보고한 `$image.Source` 실패 당시 파일/객체는 확보하지 못했다. 당시 객체 타입의 원인을
확정하지 않는다. 새 구현은 타입을 명시한 WPF Image에 Source/Stretch를 할당하고 창 없이 검증한다.

현재 세션은 `HERDR_ENV=1`인 Herdr pane이 아니다. Herdr 스킬의 외부 세션 조작 금지 지침에 따라
Herdr CLI 세션 조작은 하지 않았다. 일반 OS 프로세스·프로필·관련 이벤트만 읽었다.
확인한 사용자 PowerShell 프로필 경로에서 관련 시작 항목은 발견하지 못했다. 모든 Windows
시작 경로/예약 작업을 전수 감사한 것은 아니다.

기존 run-live/viewer 진입점은 로컬에서 새 opt-in 스크립트로 연결했고, 원본은 보존했다.
기존 진단 스크립트에는 실행 가드를 추가했다. ignored artifacts의 이 변경은 Git으로 이동하지 않으므로
지속적으로 사용할 정식 진입점은 `scripts/` 아래 파일이다.

## 재현 명령

PowerShell에서 저장소 루트로 이동한 뒤:

```powershell
$env:DOTNET_ROOT = "$env:USERPROFILE\.dotnet"
$env:PATH = "$env:DOTNET_ROOT;$env:PATH"
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-Headless.ps1

# 로컬 정적 이미지 사용, 창/화면 캡처 없음. 이 fixture는 Git에 포함하지 않는다.
dotnet run --project tools/ProtectionProbe/ProtectionProbe.csproj -c Release -- models artifacts/live-test/david.jpg
```

프로세스 범위의 ExecutionPolicy 옵션은 시스템 설정을 저장하지 않는다.
이 환경에서는 VSTest/MSBuild 자식 프로세스 통신 때문에 Codex 실행 격리 밖의 로컬 실행이 필요했다.

대화형 시험은 사용자가 화면 사용을 허용하고 기존 앱을 직접 닫은 뒤에만 실행한다:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Invoke-InteractiveValidation.ps1 `
  -Interactive -ImagePath "C:\explicit\test-image.jpg" `
  -AppPath "C:\explicit\VeilDesk.App.exe" -DurationSeconds 60
```

기본 이미지는 없다. 스크립트는 보호를 자동으로 켜거나 다시 켜지 않는다. Start는 사용자가 누른다.
창은 최대 지정 시간 후 닫힌다. Ctrl+C의 finally는 이 실행에서 생성한 앱/뷰어만 정리한다.
사용자 Stop/비상키 동작, 이동 중 검출 영역, 실제 화면 위치, 두 번째 모니터와 DPI 전환을 확인한다.
**실제 Ctrl+C 중단·물리 화면 배치·전역 비상키 입력은 NOT RUN**이다.

## 게이트

- M0: 소스 보존, 재현 가능한 headless 진입점 PASS. Herdr 원래 장애 분석 PARTIAL.
- M1: 단위 회귀 및 실제 파이프라인 정지/Stop/불투명 합성 PASS. 실제 화면 깜박임 판정 PARTIAL.
- M2: 실제 로컬 모델→추적→마스크→픽셀 합성 PASS(정적). 데스크톱→오버레이 E2E NOT RUN.
- M3/M4: 추적 누락·스크롤·음수 좌표 합성 회귀 PASS. 이동 영상·물리 복수 모니터 NOT RUN.
- M5: 실제 정적 검출 마스크 합성 PASS. 앱 녹화·실제 검출을 포함한 데스크톱 내보내기 NOT RUN.
- M6–M10: 이번 안정화 게이트가 완료될 때까지 제품 완성 판정을 보류한다. 패키지는 엔지니어링 미리보기다.

Windows compositor, 캡처 주기, 모델 지연 및 오검출 때문에 새 콘텐츠의 선행 차단/무노출을 보장하지 않는다.
정적 이미지의 합성 성공은 실제 화면의 오버레이 위치 또는 검출 정확도 증명이 아니다.
