## 확인된 원인과 구현 수정

1. 얼굴 속도를 지연된 평활 상자로 계산해 멈춘 뒤에도 가짜 속도가 생겼다. 미검출 뒤에는 해당 얼굴의 관측 간격 대신 전체 추적기의 직전 갱신 간격으로 나눠 속도를 과대 계산했다. 최신 원시 관측 상자·얼굴별 관측 시간으로 수정했다. 실패를 먼저 확인한3개 회귀가 수정 후 통과했다.
2. 얼굴 미검출 유지2초 동안 위치를 계속 외삽하고, 예측 상자와 원래 상자의 큰 bounding union을 만든 뒤 시간/속도 여백과 저신뢰도50% 확장을 중복 적용했다. 실제189×181px 상자가2308×1366px, 516×512px 상자가2007×1600px까지 확대되는 것을 좌표에서 확인했다. 후자는 화면의78.4%였다.
3. 새 `FaceMaskGeometry`는 **원시 검출 얼굴 전체 + 최대 얼굴 크기25%의 국소 위치 예측 + 기본12% 여백**을 사용한다. 고정 MaskExpansion 기본6px도 유지한다. 불확실 후보는 추가12%를 한 번만 적용하고 불투명 검은 가림을 유지한다. Detection 화면에서 Face margin을0–30%로 조절할 수 있다.
4. 시간 유지와 공간 확장을 분리해, 미검출 유지 중 마스크가 계속 커지지 않게 했다. 유지 시간2초와 ConfidenceGate/CoverageGuard, 전역 캡처/추론 실패·오래된 증거의 Fail-Closed는 유지했다. 기존 해부학적/사람 기하는 변경하지 않았다.
5. 이 변경은 미래 위치의 넓은 추정 영역을 제한한다. 최신 검출 상자 전체 포함은 보장하지만 빠른 이동 중 다음 분석 전의 실제 얼굴 위치까지 보장하지 않는다. **무노출/표시 전 검열을 주장하지 않는다.** 이미 사라진 얼굴 위치의 최대2초 잔상은 보수적 유지 정책으로 남을 수 있다.
6. YuNet 검출 상자 자체가 실제 얼굴보다 크거나 잘못된 경우에는 기하 제한만으로 얼굴 경계를 복구할 수 없다. 이 경우에는 별도 정답 자료와 ROI 재검출/검증이 필요하다. 낮은 신뢰도 후보를 일괄 버리거나 임계값을 올려 시연만 매끄럽게 만들지 않았다.

YuNet의 출력은 얼굴 bounding box·landmark·score이다([공식 API](https://docs.opencv.org/4.x/df/d20/classcv_1_1FaceDetectorYN.html)). 현재 확인된 주원인이 후처리 확장이므로 모델 교체나 브라우저 주입보다 기존 얼굴 상자 중심의 국소 기하 제한을 먼저 적용했다. 보편적으로 최적이라고 주장하지 않으며 실제 인스타그램의 다양한 사진/영상/작은 얼굴 정확도는 별도 검증 대상이다.
